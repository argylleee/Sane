| D-15 | Add a production Content Security Policy (self plus the explanation-model download hosts only), self-host the OCR English and Filipino language data from pinned MIT packages, and raise colour contrast to WCAG AA in the default themes with a separate readable text colour for the mint brand colour | October 11, 2026 audit of the latest repo. The CSP is added to the built page only (the dev server needs inline scripts) and was tested in a real browser: a text check, a Filipino screenshot read and the update flow ran with no violations and no requests to other sites. Screenshot reading no longer fetches from a public CDN, so it works offline from first use; the service worker's CDN rules were removed. Contrast was computed from the real tokens: light and dark default themes now pass 4.5:1 for text pairs (high-contrast mode already did); the raw mint colour stays for fills only. Also addresses an iOS report that "Update now" opened the browser. The reporter confirmed the likely cause: iOS lets people add a plain Home Screen shortcut that opens in Safari instead of installing the app, and nothing in the update flow can change that. iOS has no install prompt, so the Install button there only shows instructions; those now say to open Sane in Safari, choose Add to Home Screen, keep Open as Web App on, and open Sane from the new icon. For an app that is installed properly, the update now navigates to the app's own in-scope root instead of reloading the open URL, the service worker never stores a redirected page response, and `sw.js` is always revalidated (`updateViaCache: none`). No iOS device was available: the update flow was verified in Chrome only. Not yet tested on a real phone or with the optional explanation model under the CSP |
